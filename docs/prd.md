## 二、产品背景与目标

### 2.1 背景

开发者、测试、产品经理、运营等角色在日常工作中频繁使用各类小工具，包括：

- JSON / YAML / XML / CSV 等数据格式处理；
- Base64、URL、Unicode、Hash、JWT 等编码与加密；
- 时间戳、UUID、进制、正则、Cron、HTTP 状态码等开发调试；
- 文本去重、排序、统计、大小写转换；
- Markdown 实时编辑与预览；
- 图片压缩、格式转换、图片与 Base64 互转。

这些工具通常分散在多个网站，存在入口分散、体验参差、广告干扰、隐私不可控、功能之间缺少联动、没有统一收藏和历史记录等问题。

参考 BeJSON 等工具站，其优势是功能覆盖广，但常见问题包括：页面布局不统一、搜索效率低、错误提示弱、移动端体验差、刷新后输入内容丢失。本项目不逐页复制竞品，而是以“功能广度 + 现代交互深度”为目标，通过统一布局、本地优先处理、搜索直达和清晰的错误反馈建立差异。

### 2.2 竞品痛点与本产品对策


| 常见痛点           | 本产品对策                                        |
| -------------- | -------------------------------------------- |
| 工具太多，找不到入口     | 全局搜索 + `Cmd/Ctrl + K` 命令面板，支持名称、别名、标签、功能描述匹配 |
| 每个工具布局不同，学习成本高 | 所有工具必须归入布局 A / B / C，禁止单独设计页面结构              |
| 报错信息看不懂        | 文本类工具显示行列号，输入框内标红错误位置，并给出修复建议                |
| 刷新或隔天回来内容丢失    | 每个工具独立保存最近一次输入，提供“恢复上次内容”提示                  |
| 复制、下载操作繁琐      | 所有输出区固定悬浮复制 / 下载按钮，操作后轻量 Toast 提示            |
| 移动端难以使用        | 桌面双栏在移动端折叠为上下结构或“输入 / 结果”Tab，操作栏固定底部         |
| 加密工具误用敏感数据     | 页面明确提示纯前端处理，并提醒不要输入生产密钥                      |


### 2.3 产品目标

**业务目标**

1. 提供覆盖数据格式、编码加密、开发调试、文本、图像、Markdown 的综合工具站；
2. 支持搜索直达工具，提升使用效率；
3. 形成高频工具入口，沉淀用户；
4. 支持收藏、最近使用、快捷入口，提高复用率；
5. 后续可扩展为账号、云端同步、团队工具集、API 服务。

**用户目标**

1. 快速找到需要的工具；
2. 输入内容后立即获得结果；
3. 支持复制、下载、清空、示例、格式化；
4. 支持 Markdown 实时编辑与预览；
5. 尽量纯前端处理，减少隐私数据上传风险。

**体验目标**

1. 工具统一交互范式；
2. 输入即处理或点击处理，反馈明确；
3. 错误提示可读、可定位；
4. 支持深色模式；
5. 支持快捷键、搜索和移动端使用。

### 2.4 设计原则


| 原则          | 说明                                 |
| ----------- | ---------------------------------- |
| 工具优先        | 首页和搜索都以工具直达为核心                     |
| 即时反馈        | 输入、解析、转换结果应尽快展示                    |
| 本地处理优先      | 文本、图片、编码类能力尽量在前端完成                 |
| 统一交互        | 所有工具遵循统一的输入、输出、复制、下载、清空规范          |
| 布局收敛        | 所有工具必须使用布局 A / B / C，不为单个工具单独设计页面  |
| 安全透明        | 明确提示哪些工具纯前端处理，哪些需要服务端              |
| 可扩展         | 新工具通过统一配置和模板快速接入                   |
| 功能广度 + 交互深度 | 覆盖高频工具，同时在错误定位、草稿恢复、移动端等体验上优于传统工具站 |

## 四、产品定位与范围

### 4.1 产品定位

一个面向开发者和内容处理场景的**轻量级在线工具箱**，具备：

- 工具聚合与分类导航；
- 全局搜索和命令面板；
- 统一的输入输出体验；
- 本地优先处理；
- Markdown 实时编辑预览；
- 收藏、最近使用、本地草稿；
- 深色模式和响应式布局；
- 可扩展的工具注册机制。

产品对标传统工具站的功能覆盖度，但不复制其页面结构。差异化重点为：统一布局、搜索直达、错误可定位、内容可恢复、移动端可用、隐私透明。

### 4.2 范围边界

**本期纳入**

- 数据格式：JSON、YAML、XML、CSV、Properties、Query、JSONPath 等；
- 编码加密：Base64、URL、Unicode、Hex、Hash、AES、RSA、JWT 等；
- 开发调试与代码处理：时间戳、UUID、正则、进制、HTTP 查询、SQL / HTML / CSS / JS 格式化、代码对比、Cron、UA、URL 解析等；
- 文本处理：去重、排序、统计、多行处理、HTML 清理等；
- Markdown 实时渲染；
- 图像处理：压缩、格式转换、图片与 Base64 互转、二维码、GIF 等；
- 全局能力：搜索、收藏、最近使用、草稿、主题、快捷键、分享。

**明确不纳入当前版本**

- 生活、健康、娱乐、房产、育儿、血型、起名、地图拾取等非开发者工具；
- MD5 解密、JS Eval 加密、Type7 等弱算法或高风险工具；
- 视频剪辑、视频转音频、在线 Photoshop 等重多媒体编辑能力；
- 在线数据库设计、MongoDB 管理、网络拓扑图等重型应用；
- 依赖服务端的网络诊断、OCR、翻译等能力，后续按需评估。

**需要服务端或第三方 API 的能力**

IP 归属地查询、DNS / SSL / 网站信息查询、HTTP / WebSocket 请求模拟、在线代码运行等，统一标记为 P2，并在页面明确提示数据流向。

### 4.3 功能全景与优先级

#### 优先级与版本口径

- **P0**：必须交付，缺失则产品不可用；
- **P1**：应交付，按优先级排期；
- **P2**：可延后，按后续迭代推进；
- **V1（已上线）**：当前唯一版本口径，包含全部 7 大分类 91 个工具；P0 / P1 / P2 仅表示优先级，不对应独立版本。

### 6.4 主题模式

| ------- | --------- | -------- | --- |
| GLB-201 | 浅色 / 深色模式 | 支持手动切换   | P0  |
| GLB-202 | 跟随系统      | 默认跟随系统主题 | P1  |
| GLB-203 | 主题记忆      | 保存用户选择   | P0  |

- 深色模式下所有工具、编辑器、预览区和错误提示均可读；
- 主题切换不刷新页面；
- 代码高亮主题与整体主题保持一致。

### 6.5 统一操作矩阵

所有工具遵循统一操作规范。


| 操作     | 说明              | 优先级 |
| ------ | --------------- | --- |
| 复制结果   | 一键复制输出内容        | P0  |
| 下载结果   | 支持下载为文本、代码或图片文件 | P1  |
| 清空     | 清空输入和结果         | P0  |
| 示例     | 填充示例数据          | P1  |
| 格式化    | 对可格式化内容执行格式化    | P0  |
| 交换输入输出 | 部分双向工具支持输入输出互换  | P1  |


交互要求：

- 所有输出框右上角固定悬浮“复制”“下载”按钮；
- 复制成功后按钮短暂显示“已复制”，并触发 Toast；
- 下载成功后 Toast 提示“已开始下载”；
- 清空操作需要二次确认或提供撤销机会，避免误删长文本；
- 主要操作按钮不超过 5 个，细分选项收进动态参数面板。

### 6.6 错误提示与智能定位

**错误提示原则**

1. 明确说明错误类型；
2. 尽量指出错误位置；
3. 提供修复建议；
4. 不打断用户输入。

**示例**


| 场景          | 提示                                 |
| ----------- | ---------------------------------- |
| JSON 格式错误   | `JSON 解析失败：第 3 行第 12 列缺少逗号`        |
| Base64 解码失败 | `Base64 格式不正确，请检查字符是否合法`           |
| 正则错误        | `正则表达式语法错误：未闭合括号`                  |
| 图片格式不支持     | `仅支持 JPG / PNG / WebP / GIF / BMP` |
| JSON 转实体类失败 | `JSON 第 6 行缺少逗号，修正后将自动重新生成代码`      |


**智能定位要求**

- JSON / XML 校验失败时，在输入框对应行显示红色波浪线；
- 光标自动跳转到错误位置；
- 错误信息同时出现在输入区和状态栏；
- 修正后自动重新校验，不需要手动刷新；
- 输出区在错误未修复时展示友好空状态，而不是残留旧结果。

**错误区结构**

```text
[错误图标] 错误标题
错误位置：第 X 行，第 Y 列（如适用）
错误原因：缺少逗号
建议：检查对象字段之间是否缺少英文逗号。
[定位错误] [清空输入] [填充示例]
```

要求：

- JSON / XML / 代码类错误必须包含位置、原因与修复建议；
- Base64 解码失败说明非法字符、空格或换行问题；
- 图片处理失败说明不支持的原因、支持格式与“重新上传”入口；
- 错误区不遮挡输入与主操作，修正后自动消失。

| 编号      | 需求                                   | 优先级 |
| ------- | ------------------------------------ | --- |
| I18N-001 | 中文 / English 一键切换，即时生效、无需刷新        | P0  |
| I18N-002 | 语言选择持久化到 localStorage，刷新与跨页面保持     | P0  |
| I18N-003 | `<html lang>` 与 `document.title` 随语言同步 | P0  |
| I18N-004 | 非中文浏览器首次访问默认英文，中文浏览器默认中文           | P1  |
| I18N-005 | 91 个工具文案、错误提示、参考数据全量双语             | P0  |
| I18N-006 | 搜索中英互通：查询可命中中英文工具名、别名与描述           | P1  |
| I18N-007 | 英文界面按 `nameEn` 字母序排列（分类分组不变）        | P1  |

实现口径：

- 纯客户端切换，**不引入 `/en/` 路由前缀**，URL 与分享链接不变；零第三方 i18n 依赖。

- `ToolError` 同时携带双语消息，`error.message` 保持中文以兼容既有断言；参考数据集（端口、HTTP 状态码 / 方法 / Header、MIME、UA、Linux 命令、正则模板）字段全部 L10n 化。
- 工具内示例数据、检索用中文标签（tags）保持中文，不属于翻译范围。

## 七、统一工具页设计规范

### 7.1 三种标准布局

所有工具必须归入以下三种布局之一，禁止为单个工具单独设计页面结构。


| 布局           | 适用范围                                            |
| ------------ | ----------------------------------------------- |
| 布局 A：智能双栏转换型 | JSON 格式化、XML 转 JSON、Base64、URL 编解码、代码格式化、大小写转换等 |
| 布局 B：复杂参数配置型 | 图片压缩、正则测试、随机密码、Cron 解析、二维码生成等                   |
| 布局 C：沉浸式工作区  | Markdown 实时渲染、在线代码运行 Web IDE                    |


### 7.2 布局 A：智能双栏转换型

适用于约 70% 的转换类工具。

```text
┌──────────────────────────────────────────────────────────────┐
│ 工具名称                                      [收藏] [分享] [历史] │
│ 一句话说明，指导用户如何使用。                                  │
├──────────────────────────────────────────────────────────────┤
│ [动态参数面板] 根据工具变化，例如：缩进 [2 空格 ▼] [✓] 高亮      │
├──────────────────────────────────────────────────────────────┤
│ [执行 / 转换] [交换输入输出] [复制结果] [下载] [清空]           │
├──────────────────────────────┬───────────────────────────────┤
│ 左侧：输入区                  │ 右侧：输出区                    │
│ 带行号、语法高亮              │ 带行号、高亮 / 预览              │
│                              │                               │
│ {                            │ {                             │
│   "name": "test"             │   "name": "test"              │
│ }                            │ }                             │
└──────────────────────────────┴───────────────────────────────┘
```

要求：

- 桌面端左右比例默认 50:50，可拖拽调整；
- 输入区支持行号、语法高亮、括号匹配；
- 输出区支持复制、下载、格式化；
- 移动端折叠为“输入 / 结果”Tab 或上下结构。

### 7.3 布局 B：复杂参数配置型

适用于需要较多参数或文件输入的工具。

```text
┌──────────────────────────────────────────────────────────────┐
│ 工具名称                                                      │
├──────────────────────────────────────────────────────────────┤
│ [配置区]  密码长度 [16]  [✓] 大写  [✓] 小写  [✓] 数字  [✓] 符号 │
├──────────────────────────────────────────────────────────────┤
│ [输入区]  拖拽上传图片，或点击选择文件                          │
├──────────────────────────────────────────────────────────────┤
│ [生成 / 处理] [复制] [下载]                                    │
├──────────────────────────────────────────────────────────────┤
│ [结果区]  文本、图片预览、列表或文件信息                        │
└──────────────────────────────────────────────────────────────┘
```

要求：

- 配置项使用表单控件，避免藏在下拉菜单深处；
- 配置变化后尽量实时预览；
- 文件类工具显示文件名、格式、大小、尺寸等元信息；
- 处理中显示进度或骨架屏。

**文件列表**

```text
文件名 | 原大小 / 原格式 | 处理后大小 / 目标格式 | 处理状态 | 操作
```

要求：

- 每行展示处理状态：待处理、处理中、已完成、失败；
- 操作列提供预览、下载、删除；
- 批量处理完成后显示成功 / 失败数量与总计节省空间；
- 失败项保留在列表中，可重试或移除。

### 7.4 布局 C：沉浸式工作区

适用于 Markdown 和在线代码运行。

```text
┌──────────────────────────────────────────────────────────────┐
│ 工具名称                                    [编辑] [分栏] [预览] │
├──────────────────────────────────────────────────────────────┤
│ [工具栏] H1 H2 B I Link Image Code Table                     │
├──────────────────────────────┬───────────────────────────────┤
│ 左侧：源码编辑区              │ 右侧：实时预览区                │
│ Monaco / CodeMirror          │ 安全过滤后的 HTML               │
│                              │                               │
│ # Hello                      │ Hello（h1）                    │
└──────────────────────────────┴───────────────────────────────┘
```

要求：

- 编辑 / 分栏 / 预览模式切换不丢失内容；
- 同步滚动可开关；
- 移动端默认单栏，通过 Tab 切换编辑与预览；
- 预览区必须经过安全过滤。

### 7.5 通用页面结构


| 区域   | 内容             |
| ---- | -------------- |
| 顶部   | 工具名称、收藏、分享、历史  |
| 说明区  | 工具用途、使用说明、注意事项 |
| 参数区  | 动态参数面板，按需显示    |
| 输入区  | 文本框、上传框、表单参数   |
| 操作区  | 执行、清空、示例、复制、下载 |
| 结果区  | 结果展示、预览、错误提示   |
| 相关工具 | 同模块其他工具推荐      |


### 7.6 动态参数面板

- 位于工具说明下方、编辑区上方；
- 使用浅灰背景或细边框，与主编辑区区分；
- 参数项最多两行，超出时折叠为“高级设置”；
- 常用参数外露，低频参数收起；
- 参数变化后尽量实时生效；
- 移动端默认折叠为“高级设置”。

### 7.7 输入框规范


| 场景    | 规范                  |
| ----- | ------------------- |
| 长文本   | 使用等宽字体              |
| 代码类输入 | 支持 Tab、行号、语法高亮、括号匹配 |
| 普通文本  | 自动高度或可拖拽调整          |
| 文件上传  | 支持拖拽、点击、粘贴图片        |
| 大文本   | 超过阈值时使用虚拟滚动或折叠      |
| 错误输入  | 错误行标红，显示可读错误信息      |


### 7.8 按钮规范


| 按钮           | 类型        |
| ------------ | --------- |
| 执行 / 转换 / 生成 | 主按钮       |
| 复制           | 次按钮       |
| 下载           | 次按钮       |
| 清空           | 文本按钮或危险按钮 |
| 示例           | 文本按钮      |


要求：

- 页面主按钮不超过 5 个；
- 细分选项放入动态参数面板；
- 危险操作需要确认或撤销；
- 按钮 loading 状态明确，避免重复提交。

### 7.9 反馈与状态


| 场景    | 反馈                |
| ----- | ----------------- |
| 复制成功  | Toast：已复制         |
| 下载成功  | Toast：已开始下载       |
| 清空完成  | Toast：已清空         |
| 解析失败  | 错误区域展示，输入框标红      |
| 处理中   | 按钮 loading 或骨架屏   |
| 大文件处理 | 进度条               |
| 无结果   | 友好空状态，不使用系统 Alert |
| 实时生成  | 显示“生成中”微动画，完成后恢复  |


**空状态**


| 场景     | 文案与操作                  |
| ------ | ---------------------- |
| 收藏为空   | “还没有收藏任何工具”，引导去全部工具页   |
| 最近使用为空 | “最近还没有使用过工具”，引导去全部工具页  |
| 搜索无结果  | “没有找到相关工具”，提供搜索建议与推荐工具 |
| 输出为空   | 展示输入提示或示例入口，不展示空白框     |
| 列表为空   | 说明原因并提供上传、刷新或清空筛选入口    |


**加载状态**


| 场景     | 展示                   |
| ------ | -------------------- |
| 按钮执行   | 按钮文案变为“处理中…”，禁用重复点击  |
| 页面首次加载 | 骨架屏，避免布局跳动           |
| 文件处理   | 文件名、进度条、百分比；耗时任务提供取消 |
| 图片批量处理 | 显示当前文件与总体进度          |
| 路由切换   | 顶部进度条或局部骨架屏，不阻塞已加载内容 |


**Toast 文案**

```text
已复制
已下载
已清空
已收藏
已取消收藏
转换成功
处理失败
```

Toast 不阻断操作，出现在页面底部或顶部居中，不遮挡主操作；同一时间只展示一条，连续操作合并更新；错误类 Toast 需同时保留页面内错误说明。

### 7.10 响应式与移动端


| 断点                | 规则                             |

**平板端**

- Markdown 不做左右分栏，使用“编辑 / 预览”Tab 切换。

移动端要求：

1. 取消左右分栏，改为上下结构或 Tab 切换；
2. 动态参数面板默认折叠为“高级设置”；
3. 复制、下载等主操作固定在底部，导航收进抽屉，搜索保留在顶部；
4. 编辑器保持可输入、可滚动，不出现横向溢出；
5. 图片上传支持相册选择与拍照入口（如浏览器支持）。

```text
┌──────────────────────────────┐
│ < 返回    JSON 转实体类  [收藏] │
├──────────────────────────────┤
│ [高级设置（点击展开）]          │
├──────────────────────────────┤
│ Tab: [输入 JSON] [查看代码]    │
├──────────────────────────────┤
│                              │
│  { "name": "test" }          │
│                              │
├──────────────────────────────┤
│ [复制结果]      [下载文件]     │

```

## 十二、Markdown 实时渲染模块

### 12.1 定位与页面布局

Markdown 实时渲染是重点高频工具，采用布局 C，作为独立一级入口。

**三种模式**


| 模式  | 布局                  | 适用场景              |
| --- | ------------------- | ----------------- |

| 分栏  | 左侧源码、右侧实时预览，默认同步滚动  | 桌面端默认模式，边写边看      |

│ Markdown 实时渲染                              [收藏] [分享] [历史] │

│ [编辑模式] [分栏模式] [预览模式]   [复制] [下载] [清空] [示例]    │

移动端默认单栏，通过“编辑 / 预览”Tab 切换；工具栏和主操作固定在底部或顶部。

### 12.6 安全渲染要求

必须防止 XSS。

**禁止执行的内容**

```html

javascript:

onerror
iframe
object
embed
```

**建议方案**

```text
Markdown 解析器 -> HTML -> sanitize -> 渲染
```

要求：

- 使用 DOMPurify 或 sanitize-html；
- 禁止内联事件处理器；
- 外链添加 `rel="noopener noreferrer"`；
- 图片加载失败时展示占位提示；
- 预览区提供安全提示：`预览内容已进行安全过滤，不会执行脚本。`

## 二十一、风险与应对


| 风险                | 影响    | 应对方案                                   |
| ----------------- | ----- | -------------------------------------- |
| 工具数量多，开发周期长       | 上线延期  | 按 V1 分期，严格控制 V1 范围     |

| 加密工具被误用于敏感数据      | 安全风险  | 页面提示不要输入生产密钥，不保存密钥                     |

| localStorage 容量不足 | 草稿丢失  | 设置上限、提示清理、异常降级                         |
| 移动端编辑器体验差         | 用户流失  | 单栏 Tab、底部操作栏、限制大文档编辑                   |

## 二十二、附录 A：参考工具全景与取舍

### A.1 处理说明

补充文档中曾列出大量参考工具，其中包含大量重复项、非开发者工具和需要服务端的能力。本 PRD 对其做了以下处理：

1. 同一功能的不同名称合并为一个工具；
2. 同类小工具合并到统一工具或 P2 工具组；
3. 与开发者、内容处理无关的生活类工具排除；
4. 弱算法、高风险工具排除；
5. 需要服务端且不属于核心场景的能力后置到 V1 或后续。

### A.2 参考分类处理结果


| 参考分类    | 处理结果                            | 说明                                                                |
| ------- | ------------------------------- | ----------------------------------------------------------------- |
| JSON 工具 | 合并为 JSON 全家桶                    | 格式化、校验、压缩、视图、转义、互转、Path、Diff、多语言实体类；SQL、TOML、Schema、合并、排序、清理列为 P2 |
| XML 工具  | 合并到 JSON ↔ XML 与 XML 工具         | 格式化、压缩、校验、树形视图、转义；XPath 放 P2                                      |
| 前端代码    | HTML / CSS / JavaScript 格式化与压缩  | 进入 V1；多语言代码格式化放 P2                                               |
| 编码转换    | Base64、URL、Unicode、Hex、Morse、进制 | Base32 / 58 / 62 / 100、Punycode 放 P2                              |
| 加密解密    | MD5、SHA、AES、RSA、JWT             | 不提供 MD5 解密、JS Eval 加密、Type7 等弱算法                                  |
| 文本处理    | 核心文本工具 + 文本增强                   | 去重、排序、统计、大小写、多行处理、HTML 清理；娱乐型文本效果放 P2 或排除                         |
| 开发调试    | 时间、UUID、正则、查询、Cron、UA、URL、代码格式化 | 网络诊断、HTTP / WebSocket 模拟需服务端，放 V1 或后续                           |
| 图像处理    | 压缩、格式转换、图片 ↔ Base64、二维码、GIF     | 视频、在线 Photoshop、PDF 重编辑等不纳入当前版本                                   |
| 其他实用工具  | 颜色、文件大小、随机数、人民币大写、Web IDE       | 生活计算器、健康、育儿、房产、地图拾取等全部排除                                          |


### A.3 明确排除的工具类型

- 生活娱乐：起名、血型、生肖、健康指数、反应速度测试、色盲测试等；
- 家庭计算：房贷、装修、瓷砖、窗帘、油耗、育儿补贴等；
- 地理地图：地图拾取、经纬度定位、公历农历转换等；
- 内容社区：音乐播放器、图片出处查询、微博查询等；
- 弱 / 高风险：MD5 解密、JS Eval 加密、Type7、任意代码执行类工具；
- 重型媒体：视频剪辑、视频转音频、在线 Photoshop；
- 重型应用：在线数据库设计、MongoDB 管理、网络拓扑图。

### A.4 取舍原则

- 优先覆盖“开发者每天会用”的工具；
- 优先选择可纯前端实现、隐私友好的工具；
- 优先选择能复用布局 A / B / C 的工具；
- 不为了数量引入维护成本高、使用频率低的功能；
- 任何新工具进入版本规划前，必须明确场景、优先级、隐私属性和验收标准。

### B.5 建议 UI 设计顺序

```text
第一步：全局框架
顶部导航、侧边栏、页脚、主题切换

第二步：首页
搜索区、快捷标签、最近使用、收藏、分类工具卡片

第三步：通用工具页模板
单输入输出、双栏转换、文件上传

第四步：重点工具页
JSON 格式化、Markdown 实时渲染、正则表达式测试、图片压缩

第五步：列表与状态页
全部工具、分类、收藏、最近使用
空态、错误态、加载态、搜索无结果
```

原型评审至少覆盖：桌面端框架、移动端框架、三种通用布局、Markdown 三种模式、图片上传与处理状态、空态 / 错误态 / 加载态。
